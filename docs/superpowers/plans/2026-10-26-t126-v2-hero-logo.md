# T-126 V2: clay-pot hero, happy-pot logo, calm site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repo the builder is the `frontend` team agent, then `tester`, then `reviewer` (CLAUDE.md Team section).

**Goal:** Replace the red "Grandma's table" look with clay-pot colours, a calm no-pattern site, a new happy-pot logo and a home hero with a drawn GTA map (tappable demo pots) and a family-table drawing.

**Architecture:** Colours stay CSS custom properties in `src/app/globals.css` with the same names, so every page recolours from one file. The hero is server-rendered static SVG plus one small client component (`PotMap`) that holds which pot is open and fetches the chef link. The demo dish data is a typed constant that a unit test checks against `scripts/seed-data.ts`.

**Tech Stack:** Next.js App Router, TypeScript, Tailwind CSS v4, Vitest (jsdom), Playwright (mock config `playwright.mock.config.ts`, real config `playwright.config.ts`), axe via `expectNoAxeViolations` in `e2e-mock/helpers.ts`.

**Spec:** `docs/superpowers/specs/2026-10-26-hero-logo-design.md`

## Global Constraints

- No new npm packages. No WebGL or `three`. CSS and inline SVG only.
- No photos, no faces, no hands. No gingham, stripes, lace edges or pattern bands anywhere (`--gingham`, `--cloth`, `.hero::after` lace, and the h1 ribbon all go).
- Token **names** stay the same. Values per Task 1.
- Caramel `#c98a3a` is decoration only, never text.
- All text 4.5:1 or more, controls and focus 3:1 or more (WCAG 2.2 AA), light and dark.
- Motion only on hover, focus or tap (at most one gentle hint cycle on load). `prefers-reduced-motion: reduce` means no movement and instant state changes.
- Copy, exactly: H1 `Miss your mom's cooking?`. Price line `A grandma or mom near you cooks the food you grew up with, in your kitchen or hers. For less than eating out every day.` Button `Find a home cook` → `/search`. Link `I love to cook` → `/signup` (the sign-up form, where the visitor picks "chef"; no pre-selection, which would be a new feature). Map hint `Tap a pot on the map: who is cooking near you?`. Empty card `Neighbours are cooking.` + `Pick a pot to see the dish, the cook and how long it takes.` The PROTOTYPE badge stays.
- MOCK badge colours and status colours (success, warning, danger) are unchanged.
- Impeccable is **invoked** (context + detect), with output pasted in `.team/handoffs/T-126-frontend.md`. Work done "by hand" is sent back.

## Review Focus

1. **Danger red vs terracotta:** `--danger #a3201f` and `--primary #a5482a` are only 1.28:1 apart, so an error can look like a button. Error messages must keep their icon or text label. The Reviewer checks the form and booking error states in the Task 5 screenshots and on `/signup` with an empty submit.
2. **Chef link when the API is slow or fails:** the card must show the fallback link `/search` at once and swap to `/chefs/<id>` only when found. It never shows a dead link or a spinner forever (Task 4 tests).
3. **Keyboard and touch on pots:** tapping the same pot twice keeps it open. Tab order is Mississauga, Brampton, Toronto. Escape is not needed (Task 4 tests).
4. **Narrow phones (320 px):** the map labels and the card must not overflow sideways (Task 5 test at 320).
5. **Search and chef pages after the hero band change:** text on `.hero` and `.band` uses `--hero-ink` and must stay readable now that the band is light (Task 1 contrast test covers the pairs; the Task 5 axe run covers `/search` and one chef page).

### Task 4: `PotMap`, the interactive map with the live card and chef link

**Files:**

- Produces: `PotMap(): JSX.Element`, no props.

Behaviour:
- A hint `<p>` (map hint copy), then one inline `<svg>` map: Brampton, Mississauga and Toronto labels, the Lake Ontario label, a soft land fill, the lake in `#bcd3f5` (dark: a deeper blue with the label 4.5:1), and roads as plain strokes. The svg has `role="img"` and `aria-label="Drawn map of Brampton, Mississauga and Toronto, not to scale"`.
- Three `<button type="button">` pots, positioned over the map, in DOM order Mississauga, Brampton, Toronto. Each `aria-label={potLabel(p)}`, `aria-pressed={open === p.key}`, hit area 44×44 or larger, focus ring `var(--focus)`.
- `open` starts as `null`. `mouseenter`, `focus` and `click` set `open = p.key`. Clicking an open pot keeps it open. Only one is open at a time.
- An open pot gets class `is-open`: the lid lifts (`translate(10px,-22px) rotate(18deg)`), steam fades in, and the dish bubble pops above it. Reduced motion means no transition.
- The card `<div aria-live="polite" data-testid="pot-card">`. With `open === null` it shows the empty copy. When open, it shows `<b>{dishName}</b>`, a DEMO badge (`.mock-badge` style, text `DEMO`), then `{chefName} · {city} · {cookTimeText}`, then a link.
- Link: `href` is `/search` at first, with text `Find a {cuisine} cook`. On mount, fetch every pot's lookup in parallel, once. When `items.find(i => i.displayName === chefName)` exists, that pot's link becomes `chefPath(id)` with text `See {chefName without " (demo)"}`, e.g. `See Chef Lan`. A fetch error or a missing chef keeps the fallback, with no console error.
